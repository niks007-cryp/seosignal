# Deployment Notes

SEOSignal is deployed to Vercel production at **[https://seosignal.vercel.app](https://seosignal.vercel.app)**. The connected private source repository is [github.com/niks007-cryp/seosignal](https://github.com/niks007-cryp/seosignal). The Vercel project is configured from the `main` branch.

## Vercel adapter

The application keeps the React client as a static Vite build while adapting the existing Express/tRPC API to a Vercel Node serverless function.

| Concern | Production implementation |
| --- | --- |
| Client build | `vite build` outputs to `dist/public` |
| API entry | `server/vercelHandler.ts` imports the reusable Express application factory |
| Vercel function | `scripts/build-vercel-api.mjs` bundles the handler and server modules into `api/[...path].js` |
| API routing | `vercel.json` rewrites `/api/:path*` to `/api/[...path]` |
| Function duration | `vercel.json` assigns `maxDuration: 60` to the bundled API function |

The API bundle is regenerated by `pnpm build:vercel` and intentionally committed because Vercel executes `api/[...path].js` as the function entry point.

## Required production environment variables

Configure secrets in Vercel’s production environment settings. Do not commit secret values and do not expose the server-only values through `VITE_` or `NEXT_PUBLIC_` names.

| Variable | Required | Runtime use |
| --- | --- | --- |
| `GEMINI_API_KEY` | Yes | Server-only Gemini structured qualification request |
| `GEMINI_MODEL` | Optional | Overrides the default `gemini-3.6-flash` model identifier |
| `NEXT_PUBLIC_SUPABASE_URL` | Yes | Supabase REST base URL; the server accepts an origin with or without `/rest/v1/` |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Available | Not used by the current server-side persistence path |
| `SUPABASE_SERVICE_ROLE_KEY` | Yes | Server-only writes to `leads` and `qualifications` |
| `SUPABASE_ACCESS_TOKEN` | Setup only | Used only to apply schema changes through the management API; not required by the Vercel runtime |

## Release verification

Before releasing code, run the deterministic checks locally:

```bash
pnpm check
pnpm test
pnpm build:vercel
```

The opt-in Gemini test calls the external model and is deliberately excluded from the normal deterministic suite:

```bash
GEMINI_INTEGRATION_TEST=true pnpm vitest run server/geminiQualification.integration.test.ts
```

Production validation should submit only a temporary, non-customer lead, verify report rendering and both Supabase records, then delete the temporary lead and confirm the linked qualification is cascade-deleted. See [production browser validation](production-browser-validation.md) for the completed validation record.
